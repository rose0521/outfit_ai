# 商品库对接说明（v2）

> 本文档给商品库同学。模型侧已把「商品检索 + 质量评估 + 穿搭推荐」的数据管线和接口搭好，现在需要商品库提供数据接入。本文说明你要交付哪些文件、每个文件长什么样、类目怎么归、图片有什么要求。

## 一、你要交付的三样东西

1. **商品主图**：每件商品一张，图片文件或可下载 URL；
2. **metadata.csv**：商品元数据，每行一件商品；
3. **reviews.csv**：商品评价，每行一条评价。

交付后，模型侧会自动完成「图片提特征 → 检索可用 → 评价算质量分 → 三个接口全通」。你只需保证下面三个文件的格式正确，其余步骤都是模型侧操作。

## 二、metadata.csv（商品元数据）

列（**表头必须一字不差**）：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| item_id | ✅ | 商品唯一 ID，字符串，全局唯一、长期不变 |
| semantic_category | ✅ | 类目代码，必须是第四节 11 类之一 |
| title | ✅ | 商品标题（检索结果里要展示） |
| price | 可选 | 价格，数字（展示用） |
| image_path | ✅ | 主图路径或 URL |

示例：

```csv
item_id,semantic_category,title,price,image_path
1000001,tops,白色通勤衬衫,89.0,images/1000001.jpg
1000002,bottoms,黑色直筒裤,129.0,images/1000002.jpg
```

说明：

- `image_path` 可以是相对路径（相对于 metadata.csv 所在目录，如 `images/1000001.jpg`）或 `http(s)://...` URL；
- `price` 没有就留空，不影响跑通。

## 三、reviews.csv（商品评价）

列：

| 列名 | 必填 | 说明 |
| --- | --- | --- |
| item_id | ✅ | 对应 metadata.csv 里的商品 ID |
| rating | ✅ | 评分，1~5（越高越好） |
| review_text | ✅ | 评价文本 |

示例：

```csv
item_id,rating,review_text
1000001,5,"面料舒服，版型正"
1000001,3,"有点透，尺码偏小"
1000002,4,"垂感不错"
```

说明：

- 原始数据集如果是别的评分制（10 分制、星级等），请归一化到 1~5；
- `review_text` 含逗号 / 引号时，按 csv 规范加引号（如上面示例）；
- 每条评价一行，同一件商品可以有多行。

## 四、类目（必须归到 11 类之一）

模型在这 11 个类目上训练，商品库类目需要映射到这几类：

| 类目代码 | 含义 |
| --- | --- |
| tops | 上衣 |
| bottoms | 下装 |
| shoes | 鞋 |
| bags | 包 |
| outerwear | 外套 |
| all-body | 连体 |
| jewellery | 首饰 |
| hats | 帽 |
| scarves | 围巾 |
| sunglasses | 墨镜 |
| accessories | 配饰 |

映射规则：能对上就归对应类；实在对不上的先归 `accessories`，并单独和模型侧确认。**不要自造新类目。**

## 五、图片要求

- 白底或纯色背景、单件商品、主体清晰居中；
- 常见格式均可（jpg / png / webp），能正常解码即可；
- 分辨率建议 ≥ 224×224（太小会模糊，影响特征质量）；
- 不要多件拼接图；配饰类可以带穿戴，但主体要清楚。

## 六、交接流程

1. 把主图、`metadata.csv`、`reviews.csv` 三样东西放到约定位置（建议都放 `data/processed/` 下，图片放 `data/processed/images/`）；
2. 模型侧跑 `python -X utf8 scripts/extract_features_from_files.py --limit 500` 提取图片特征；
3. 模型侧跑评价评分统计，生成质量分缓存；
4. 启动服务后，检索 / 质量评估 / 穿搭推荐三个接口即可用。

> 第 2~4 步都是模型侧操作，你只负责第 1 步文件正确。

## 七、几条约定

1. `item_id` 一旦定下就不要改（检索 / 质量 / 推荐都靠它定位商品）；
2. 同一件商品多张图时，选一张最能代表商品的做主图；
3. 类目对不上时不要乱造新类目，先归 `accessories` 再沟通；
4. 商品库更新（新增 / 下架）时，把增量同步给模型侧即可。
