## 0. 已核实的数据事实（本方案的所有决策依据）

- 特征：`data/processed/clip_features/features.npy`，shape `(71967, 512)`，float32，**已 L2 归一化**（范数恒为 1）；无 NaN/Inf、无零向量、无重复 ID。
- `item_ids.json`：71967 个字符串 ID，唯一、非空，与 `features.npy` 行一一对应。
- `train.json`：16995 套搭配，85935 条单品引用，71967 个唯一商品；**位置编号从 1 开始且每套 1..N 连续**。
- 每套商品数分布：2~16 件，以 4~6 件为主（{2:346, 3:1842, 4:4178, 5:4850, 6:3208, 7:1581, 8:639, 9:231, 10:90, 11:18, 12:9, 13:1, 14:1, 16:1}）。
- 同一商品出现在多套搭配中：9420 个商品（最大 23 次）——**这是正常现象，不是数据错误**。
- 官方已提供负样本：`compatibility_train.txt` 中 label=0 的行（16995 条，每行是"替换后"的搭配）；`fill_in_blank_train.json` 提供 16995 道填空题（每题 4 候选，1 正 3 干扰）。
- 类别信息：`polyvore_item_metadata.json` 每件商品有 `category_id` 与 `semantic_category`（tops/bottoms/bags/shoes/... 共 11 类）；`typespaces.p` 定义了合法的类别共现对。
- 官方划分：train(16995) / valid(3000) / test(15145) 套搭配。
- **跨划分商品重叠**：train∩valid=3781、train∩test=84、valid∩test=34 —— 说明"disjoint"并非严格商品不重叠，防泄漏时须注意（见第 6 节）。
- **关键陷阱**：`item_ids.json` 的行顺序 ≠ `train.parquet` 行顺序（多进程提取交错所致，36516 处不同）。**下游必须用 `item_ids.json` 建立 `item_id → 特征行号` 映射，绝不可按位置对齐。**

## 1. 正样本如何构建

**来源只取真实搭配**（`train.json`，即 `compatibility_train.txt` 中 label=1 的行），不掺任何构造对。

两个层级：

1. **商品对级（pair-level）正样本**：同一套搭配内任意两件商品 `(i, j)` 记为兼容正样本。一套 N 件的搭配产生 `C(N,2)` 个无序对（若需要方向信息则用 `N*(N-1)` 个有序对）。
   - 按当前分布，train 集约产生 **19.3 万** 个无序正样本对（有序约 38.6 万）。
2. **整套级（set-level）正样本**：整套搭配本身作为正样本，用于训练"整套兼容打分"与 FITB。

正样本标签是**强标签**（真实穿搭，人工构造），可信度高。

---

## 2. 负样本如何构建（并避免评估偏差）

**核心认知：负样本只是构造出的训练标签，不是人工验证过的"真实不兼容"。** 两个从未同现的商品，未必真的不搭。因此负样本用于"让模型学会区分真实搭配与随机/替换搭配"，而不是作为不可动摇的真值。

分三种来源，按可信度从高到低：

1. **官方替换负样本（最推荐，已有）**：`compatibility_train.txt` 中 label=0 的行。这些是数据集作者把某套真实搭配中**某一件换成另一件类别相容的商品**得到的，更接近"合理但不搭"的困难负样本。直接用作 set 级负样本。
2. **类别感知（type-compatible）替换**：用 `semantic_category` + `typespaces.p`，把搭配中某件商品替换为**同 super-category（或 typespaces 允许的类别）的其它商品**。保证替换后在"类型上说得通"，但组合是编造的。避免"上衣换裙子"这种明显荒谬、模型凭类别就能判对的简单负样本。
3. **困难负样本（hard negative）**：在特征空间里，取**与正样本商品余弦相似度高、但来自不同搭配**的商品对，或"同类别、不同搭配"的对。这类负样本最有用，但最容易产生假负样本，训练时用、评估时不单独依赖。

**避免评估偏差的关键**：

- 负样本只作为"构造标签"参与训练；**评估一律用官方任务**（CP 的 AUC、FITB 的准确率），不把"负样本判对率"当作最终指标。
- 训练时控制正负比（建议 1:1 ~ 1:3），并保证负样本的类别分布与正样本大致一致，避免模型学到类别捷径。
- 若追求更严格，可报告"测试集中有多少商品在训练集出现过"（见第 6 节），把商品级泛化与搭配级泛化分开看待。

## 3. 单品如何用 512 维 CLIP 特征表示

- 直接使用 `features.npy` 的 512 维 L2 归一化向量作为每个单品的初始表示，**零训练成本即可启动**。
- 建议在模型内加一个**可学习投影头**：`g(x) = W₂ · ReLU(W₁ · x)`，把 512 维映射到较小的 d 维（如 256）。投影头让模型在 CLIP 特征之上学习任务相关的线性子空间；CLIP 主干保持冻结，参数量极小。
- 落地方式：把 `item_id → 特征行号` 建成一张索引表（JSON 或 numpy 数组），并把特征矩阵存成单一 `.npy`。训练时按 `item_id` 查表取行，**不要再回 JSON/Parquet 解析**，也不要按 parquet 行号取。

## 4. 整套搭配的特征表示

分阶段，从简单到复杂：

1. **均值池化（mean pooling）—— 起步基线**：`z_outfit = mean(g(x_1), ..., g(x_N))`。无序、简单、稳定，先跑通全流程。
2. **注意力池化（attention pooling）**：学习每件商品对整套的权重，能捕捉"哪件是主体"。
3. **序列建模（可选）**：Polyvore 原始做法用 BiLSTM 按位置顺序编码；本项目位置顺序已知（index 1..N），若要利用顺序信息可上轻量 LSTM/Transformer。仅在前面基线稳定后再做。

推荐路线：先 1 → 跑通 CP + FITB → 再加 2 → 视收益决定是否上 3。

---

## 5. 训练 / 验证划分（防搭配间数据泄漏）

- **按搭配（set_id）粒度划分，绝不可按商品对粒度随机划分**：否则同一套搭配的多个商品对会被拆进训练集和验证集，造成严重泄漏。
- 直接采用官方划分 train / valid / test，其本身已经按搭配分好，且提供了 `compatibility_*.txt` 与 `fill_in_blank_*.json` 三个划分的现成评测文件。
- **额外的商品级泄漏风险**：由于跨划分存在商品重叠（train∩valid=3781 等），即便按搭配划分，验证集中仍有商品在训练集出现过。处理方式（择一或并用）：
  1. 接受官方划分，但在评估时**报告重叠程度**作为透明度指标；
  2. 额外做 **cold-item 评估**：只在"验证/测试集中未在训练集出现过的商品"子集上测，评估对未见商品的泛化；
  3. 若需要严格干净，可额外构造"商品不重叠"的二次划分——但这会改变官方评测口径，建议仅作诊断用，最终结果仍以官方 split 为准。
- 负样本的生成必须在划分之后、且**只在各自划分内部**进行（不能用训练集的商品去构造验证集的负样本）。

## 6. 轻量级模型（都可在 CPU 上训练）

参数量都在几十万量级，CPU 可训。三个候选，由简到繁：

1. **配对打分 MLP（pair-scoring）**：输入两件商品特征 `(g(x_i), g(x_j))`，用拼接或逐元素差/乘积作为交互，接 2~3 层 MLP，输出兼容分数。用于 pair 级 CP。
2. **整套编码 + 打分头（set encoder）**：第 4 节的池化得到 `z_outfit`，接 MLP 输出整套兼容分。**同一模型即可同时支撑 CP（打整套分）与 FITB（对每个候选算 `z(outfit∖blank ∪ 候选)` 的分数，取最高）**。
3. **对比学习（可选）**：InfoNCE + 内积相似度，适合后续做"以商品/搭配检索"的召回式推荐。

推荐起步：**模型 2（mean pooling + MLP）**，因为它一个模型同时覆盖 CP 与 FITB，且实现量最小。

---

## 7. CP 与 FITB 的评估

- **CP（Compatibility Prediction）**：给定一套搭配，输出兼容分数；用 `compatibility_{split}.txt` 的 label 1/0 计算 **AUC**。这是官方口径（真实搭配为正、替换搭配为负）。
- **FITB（Fill In The Blank）**：给定缺一件的搭配 + 4 个候选，选出正确那一件；用 `fill_in_blank_{split}.json` 计算 **top-1 准确率**（选对的比例）。
- 用 **valid 划分调参与早停**，**test 划分只跑一次出最终报告**。
- 报告时同时给出"搭配级指标"与（可选的）"商品级冷启动指标"，并注明负样本的构造方式。

---

## 8. 建议的实施顺序（评审通过后）

1. 构建"商品特征库"：`item_id → 特征行` 索引 + 单份特征矩阵（纯 numpy，不依赖 torch 加载）。
2. 构建训练样本：pair 正负样本 + set 正负样本，写入带 train/valid/test 标记的存储（npz 或 parquet），并固化负样本构造的随机种子以保证可复现。
3. 跑 mean-pooling + MLP 基线：在 valid 上测 CP-AUC 与 FITB-accuracy，确认管线正确、指标合理。
4. 迭代：加投影头/注意力池化、困难负样本、类别感知替换，逐个验证收益。
5. 全部在 test 划分上出最终结果。
