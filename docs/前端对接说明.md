# 穿搭推荐模块 · 前端对接说明

> 本文档给前端同学。后端已实现第一版穿搭推荐模型，本文说明它的能力、接口约定、Mock 数据与联调方式。

## 一、后端已实现的能力

1. **搭配兼容性打分（CP）**：输入一套搭配（若干件商品），输出 0~1 的兼容性分数，越高越搭。
2. **缺件推荐（FITB）**：输入一套"缺了一件"的搭配 + 若干候选商品，模型选出最搭的一件，用于"补全搭配 / 推荐单品"。

## 二、技术方案与当前效果

- 每件商品用 CLIP 编码成 512 维图片特征，整套搭配用"均值池化 + 轻量 MLP"打分，模型很小（约 13 万参数），CPU 即可运行。
- 基于公开数据集 Polyvore 训练，最终测试指标：
  - 搭配兼容性 AUC：**0.86**
  - 缺件推荐 Top-1 准确率：**0.57**（随机四选一为 0.25）
- 说明：这是第一版基线，指标仍有提升空间，后续会持续优化。

## 三、接口约定（草案，可调整）

后端服务默认监听 `http://127.0.0.1:8000`（本地联调）。

### 1. 健康检查

`GET /health`

响应：

```json
{"status": "ok", "model": "MeanPoolMLP", "num_items": 156659}
```

### 2. 搭配兼容性打分

`POST /api/outfit/score`

请求体：

```json
{"items": ["132621870", "153967122", "171169800", "162799044"]}
```

响应：

```json
{"score": 0.86, "items": ["132621870", "153967122", "171169800", "162799044"], "item_count": 4, "missing": []}
```

- `score` 范围 0~1，越高越搭，前端可用进度条/星级展示。
- `missing` 是"没有特征、无法参与打分"的商品 ID 列表，正常情况下为空。

### 3. 缺件推荐（补全搭配）

`POST /api/outfit/fill`

请求体：

```json
{"items": ["153967122", "171169800", "162799044"], "candidates": ["132621870", "200587578", "199321476", "180028994"]}
```

响应：

```json
{
  "best_item_id": "132621870",
  "best_score": 0.87,
  "ranked": [
    {"item_id": "132621870", "score": 0.87},
    {"item_id": "200587578", "score": 0.72},
    {"item_id": "180028994", "score": 0.61},
    {"item_id": "199321476", "score": 0.55}
  ]
}
```

- `candidates` 是候选池（收藏夹/购物车/某类目下的商品），模型从中选最搭的。
- `ranked` 是完整排序，前端展示"Top 1 推荐 + 备选列表"。

### 4. 商品信息查询

`GET /api/item/{item_id}`

响应：

```json
{"item_id": "132621870", "has_feature": true}
```

- `has_feature` 表示该商品能否参与打分；为 `false` 时前端应提示"该商品暂不支持"。

## 四、商品字段约定

- `item_id`：商品的唯一标识，纯数字字符串，如 `"132621870"`。
- `semantic_category`：商品大类，取值共 11 类：
  `tops`（上衣）、`bottoms`（下装）、`shoes`（鞋）、`bags`（包）、`outerwear`（外套）、`all-body`（连体）、`jewellery`（首饰）、`hats`（帽）、`scarves`（围巾）、`sunglasses`（墨镜）、`accessories`（配饰）。
- 真实电商数据仍在爬取中，`title`、`image_url` 等字段暂为占位，先用公开数据演示。

## 六、页面交互流程建议

1. **打分页**：用户从商品池点选几件（建议 2~8 件）→ 点"评分" → 调 `/api/outfit/score` → 显示分数 + 每件商品小图横排。
2. **补全页**：用户已选 2~3 件 → 点"补全" → 调 `/api/outfit/fill` → 展示"推荐补这一件"的商品卡 + 2~3 个备选。
3. 两页可共用一个商品选择器组件（左侧类目筛选 + 商品网格，点选加入右侧"当前搭配"区）。

## 七、边界情况（前端需处理）

1. 商品少于 2 件时打分无意义，前端置灰"评分/补全"按钮。
2. 商品多于 8 件仍可打分，但分数趋于中间值，前端可提示"建议 3~6 件效果最佳"。
3. 某商品无特征时，接口返回 `missing` 或 `has_feature: false`，前端要提示"该商品暂不支持"，不要白屏。
4. 分数是相对值，展示时用"搭配度 0.86 / 较搭 / 一般"等相对表述，不要写绝对话术。

## 八、本地联调方式

后端服务由后端同学启动（一条命令）：

```powershell
python -X utf8 scripts/serve_demo.py --port 8000
```

前端把请求地址指向 `http://127.0.0.1:8000`（同机）或 `http://<后端电脑IP>:8000`（同一局域网）。前端可先用 Mock 独立开发，联调时再切换为真实地址。
