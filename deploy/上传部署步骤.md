# outfit_ai 部署步骤（服务器已开通 · zip 上传路线）

前提：腾讯云轻量应用服务器（2 核 2G Ubuntu）已开通，用 OrcaTerm 浏览器终端登录；本地已有 `outfit_ai_deploy.zip`。

## 0. 准备

- 服务器公网 IP（浏览器访问用）、登录用户（腾讯云轻量 Ubuntu 镜像默认 `ubuntu`）
- （可选）DeepSeek API key —— 不配也能跑，`/api/chat` 会自动退回规则路由

## 1. 上传 zip 到服务器（OrcaTerm 网页终端直接传）

OrcaTerm 支持在网页终端里直接上传文件，不用再装 WinSCP / 用 scp：

1. 在轻量应用服务器控制台点「登录」，用 OrcaTerm 连上实例；
2. 把本地 `outfit_ai_deploy.zip` 直接拖进 OrcaTerm 终端窗口（或点终端工具栏的「上传文件」图标），上传到当前目录（一般是家目录 `~`）；
3. 传完执行 `ls -lh ~/outfit_ai_deploy.zip`，能看到约 2.4 MB 的文件就对了。

## 2. 解压就位

```bash
sudo apt update
sudo apt install -y unzip python3-venv python3-pip
sudo unzip ~/outfit_ai_deploy.zip -d /opt        # 得到 /opt/outfit_ai
# 登录用户不是 root 时，把目录归到你名下（下面假设 ubuntu）：
sudo chown -R ubuntu:ubuntu /opt/outfit_ai
```

## 3. 建虚拟环境 + 装依赖

```bash
cd /opt/outfit_ai
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip

# torch 必须装 CPU 版（默认会下 2G+ 的 CUDA 版）
pip install torch --index-url https://download.pytorch.org/whl/cpu

# 其余依赖（国内慢可加清华镜像）
pip install -r deploy/requirements.txt
# 慢的话换：
# pip install -i https://pypi.tuna.tsinghua.edu.cn/simple -r deploy/requirements.txt
```

> torch 从 download.pytorch.org 在国内可能很慢；若超时，改用阿里云镜像：
> `pip install torch --index-url https://mirrors.aliyun.com/pytorch-wheels/cpu`

## 4. 下载 CLIP 模型（一次性，约 605 MB）

推荐用 wget 下到项目本地目录（能看到进度、支持断点续传；python 的 `from_pretrained` 下载过程静默无输出，容易被误判卡死）：

```bash
mkdir -p /opt/outfit_ai/models/clip-vit-base-patch32
cd /opt/outfit_ai/models/clip-vit-base-patch32
BASE=https://hf-mirror.com/openai/clip-vit-base-patch32/resolve/main
for f in config.json preprocessor_config.json tokenizer_config.json special_tokens_map.json vocab.json merges.txt tokenizer.json; do
  curl -4 -L --retry 3 -o "$f" "$BASE/$f"
done
wget -4 -c "$BASE/pytorch_model.bin"
```

正常大小：`pytorch_model.bin` 577M、`tokenizer.json` 2.2M、`vocab.json` 843K、`merges.txt` 513K，其余几 KB。明显偏小的就是没下完，重下该文件。

> 若 wget 出现 `Reusing existing connection` 后卡死（hf-mirror 常见），改用 `curl -4 -L --retry 3 -o <文件> <URL>` 重下。

验证纯本地可加载（不联网）：

```bash
cd /opt/outfit_ai && source .venv/bin/activate
python -c "from transformers import CLIPModel, CLIPProcessor; p='models/clip-vit-base-patch32'; CLIPModel.from_pretrained(p, local_files_only=True); CLIPProcessor.from_pretrained(p, local_files_only=True); print('local CLIP ok')"
```

看到 `local CLIP ok` 即可。注意：启动时必须带 `--clip-model models/clip-vit-base-patch32`，否则会按模型名联网查找。

## 5. （可选）配 DeepSeek 自然语言

```bash
cd /opt/outfit_ai
echo 'DEEPSEEK_API_KEY=sk-你的key' > .env
# 自测（不起服务）：
python -X utf8 scripts/test_llm.py "帮我找一件白色衬衫"
```

## 6. 前台试跑 + 验证

```bash
cd /opt/outfit_ai && source .venv/bin/activate
python -X utf8 scripts/serve_demo.py --host 0.0.0.0 --port 8000 \
  --feature-dirs data/processed/clip_features_catalog \
  --clip-model models/clip-vit-base-patch32
```

另开一个 SSH 窗口验证：

```bash
curl http://127.0.0.1:8000/health
curl -X POST http://127.0.0.1:8000/api/recommend -H 'Content-Type: application/json' \
  -d '{"query":"预算300元以内买柔软的连衣裙","limit":3}'
```

浏览器访问 `http://你的IP:8000/health`（需先在实例「防火墙」里放行 8000）。`/health` 应显示 catalog 500 件商品（而非 15 万件），说明只加载了商品库特征。

## 7. systemd 常驻

按需改 `deploy/outfit-ai.service` 里的 `User=`（root 就改成 root 或删掉该行）：

```bash
sudo cp deploy/outfit-ai.service /etc/systemd/system/outfit-ai.service
sudo systemctl daemon-reload
sudo systemctl enable --now outfit-ai
systemctl status outfit-ai
journalctl -u outfit-ai -f      # 实时日志
```

> 首次启动加载 CLIP 要几秒到几十秒，属正常。2G 内存别同时起两个实例。

## 8. 防火墙放行端口

轻量应用服务器控制台 → 该实例 → 「防火墙」标签 → 「添加规则」：协议 TCP、端口 8000、来源 0.0.0.0/0（或填你的 IP）。注意轻量应用服务器用的是「防火墙」，不是 CVM 的「安全组」。

## 常见问题

- `/health` 商品数不对 / 搜不出 → 检查 `data/processed/clip_features_catalog/` 是否在，启动是否带了 `--feature-dirs`。
- 推荐/质量维度报错 → 检查 `vendor/fitin/runtime/fitin.sqlite` 是否在（zip 里已带，别删）。
- 中文搜索不相关 → 确认 `scripts/zh2en.py` 在（已随包）。
- 内存不足 → 确认只加载了 catalog 特征，且没同时跑两个服务。
